# Proof for 0.27.0

**Reader:** people

Each improvement below was run on the code of this release, on 2026-11-15 (see [README.md](README.md) for how a proof
is read).

## A recording that cannot work is refused before it starts

**Promise:** `perf_record` refuses, in milliseconds and with what to do, a recording that is bound to fail: a program that
is not executable, a live recording lock, too little free disk, no `xcrun`, a locked screen. No process starts and no file
is written.

**Command:** `perf_record` through the MCP server, `wine="native"`, three times: with a text file as the program; with the
lock folder (`METAL_TRACE_LOCK`) naming a live process; and with `PERF_MIN_FREE_GB=999999`.

**Output:**

```
0.0 s   notes.txt is not an executable file
0.04 s  another recording is running; one runs at a time. If none is, remove the lock folder (METAL_TRACE_LOCK names it)
0.0 s   not enough free disk on the temporary folder (TMPDIR): 66 GB free, 999999 GB needed (PERF_MIN_FREE_GB overrides)
```

The runs folder had no new file after the three calls. Messages name files, never paths.

**Where and when:** macOS 27.0.1, Apple M1 Pro, xctrace 27.2 (27B52); 2026-11-15.

**Not tested:** the locked screen on a real locked session (covered by tests that inject the reading); no `xcrun`; Windows (the
lock check never signals a process there: covered by tests, not run on Windows).

## The runs folder: compressed tables and a size limit

**Promise:** a new recording writes its per-frame and Metal memory tables as `.csv.gz`, and with `METAL_TRACE_MAX_DISK_MB` the
oldest `.trace` goes first until the folder fits; summaries and tables stay.

**Command:** `perf_record` of `drawstress` (`api=mtl`, `seconds=20`, `tier=standard`), then the size of each table plain and
gzip; then a `perf_record` (`seconds=5`, `tier=light`) with `METAL_TRACE_MAX_DISK_MB=20` over a folder that held a 99 MB `.trace`
kept by a `tier=deep` run.

**Output:**

```
frames.csv.gz        1750 lines   74025 B plain   31810 B gzip   2.3x
metal_memory.csv.gz 15757 lines  305304 B plain   53561 B gzip   5.7x

runs folder before: 101296 KiB (1 .trace)
retention: {"freed_mb": 96.84, "removed": 1, "trace_dropped": false}
runs folder after:    300 KiB (0 .trace; the deep run's .json, both tables and the samplers still there)
```

**Where and when:** same machine and date.

**Not tested:** a runs folder over the limit with only the new run's own files (`trace_dropped: true`, covered by tests); a
Windows recording (its writer is the same module, run only through tests); reading an old `.csv` run in the same session as
a `.csv.gz` one (covered by tests per tool).

## Reading a big table takes a fraction of the memory

**Promise:** `perf_report.rows` frees each row and keeps only the cells a later row refers to, so a table of millions of rows
no longer needs gigabytes, and gives the same rows.

**Command:** a `tier=deep` recording of `drawstress` (`seconds=5`) keeps a 99 MB `.trace`; four of its tables were exported
with `xctrace` and read by the code of 0.25.0 and by the new one, each in its own process (peak resident memory). The same
five tables, row by row, were hashed (tag, text, attributes and children of every cell, refs resolved) with both.

**Output:**

```
                            rows       before        after     time before / after
metal-gpu-intervals       11 896    151.1 MiB     35.7 MiB     0.5 s / 0.6 s
gpu-shader-profiler-sample 53 184   115.1 MiB     35.0 MiB     0.4 s / 0.5 s
gpu-counter-value      3 080 160  5582.7 MiB    196.4 MiB    39.9 s / 30.8 s
kdebug                 1 552 761  5523.1 MiB    304.0 MiB    47.5 s / 35.7 s
same rows (hash): metal-gpu-intervals, gpu-shader-profiler-sample, os-signpost-arg, time-profile, metal-object-label: EQUAL
```

Memory is not constant on a real trace: it follows the distinct values rows share (196 and 304 MiB here, against 3 MiB
on synthetic tables). The first pass over the file costs about 1 s on the small tables and saved time on the big ones.

**Where and when:** same machine and date; the trace was recorded that day.

**Not tested:** a trace of several gigabytes (the largest table here is 532 MB of XML); `perf_report.summarize`, which still keeps one
entry per GPU interval, so the whole summary still grows with the trace.

## tier: light, standard and deep

**Promise:** `tier` picks what a recording captures: `light` writes no Metal memory table and no counters, `standard` is what
a recording was before, `deep` also records GPU counters and keeps the `.trace` (unless the disk limit drops it); the summary
says its `tier` and `perf_compare` says when the two runs differ in it.

**Command:** `perf_record` of `drawstress` (`api=mtl`) at each tier; `perf_compare` of a light run against a standard one;
total time of `seconds=5` runs, light and standard twice each.

**Output:**

```
light    (20 s): frames.csv.gz, no metal_memory table, no .trace
standard (20 s): frames.csv.gz, metal_memory.csv.gz
deep     (5 s):  frames.csv.gz, metal_memory.csv.gz, gpu_counters in the summary, .trace kept (99 MB)
perf_compare tier: {a: light, b: standard, note: "the recordings were made at different tiers: ... compare memory only between recordings of the same tier"}
total time, 5 s runs:  standard 36.0 s, 38.0 s   light 34.2 s, 36.1 s   deep 125.7 s
```

`light` saves about 2 s of 36 on this native program: the saving is the memory table, small here. The large difference is
against `deep` (counters).

**Where and when:** same machine and date.

**Not tested:** a Wine program, where the export takes minutes and `light` should save more; `tier` on `perf_attach`;
`tier` together with an explicit `memory` or `counters` (covered by tests).

## Next actions, noisy environment and cooldown

**Promise:** `cooldown_s` rests between two consecutive recordings and never before the first or after the last;
`perf_diagnose` and `perf_compare` return `suggested_actions` (`{tool, arguments, reason}`) so an agent knows what to call
next; the summary says in `noisy_environment` when another process was loading the GPU.

**Command:** `perf_baseline_record` of `drawstress` (`api=mtl`, `seconds=8`, `count=2`, `tier=light`, `cooldown_s=20`), then the
gap between the end of run 1 (its JSON) and the first file of run 2; `perf_diagnose` and `perf_compare` on quiet runs; the
`noisy_environment` field of a quiet run. Then a second copy of `drawstress` was started by hand to load the GPU, and the
first was recorded (`perf_record`, `seconds=20`, `tier=standard`) while it ran; `perf_diagnose` and `perf_compare` (against
the quiet standard run) on that recording.

**Output:**

```
gap between the end of run 1 and the first file of run 2: 20.1 s   (tool total 111 s for two runs of about 48 s and 43 s)
perf_diagnose suggested_actions: []      perf_compare suggested_actions: []
noisy_environment (standard run with the AGX sampler): false

with a second drawstress running (1776 frames, presented all along):
noisy_environment: true  noisy_basis {gpu_device_pct_mean: 75.5, process_busy_pct: 41.1, external_pct: 34.4}
perf_diagnose suggested_actions: [{tool: perf_record, arguments: {}, reason: "<run>: another process was loading the GPU while it
  recorded: close other GPU users first and record again (with the same program arguments)"}]
perf_compare noisy_environment: {runs: [<run>], note: "another process was loading the GPU while these recorded ... repeat the run before trusting its numbers"}
```

The 20.1 s gap is the cooldown; nothing waited before run 1 or after run 2. With the second program running the flag turned
over on its own numbers (34.4 points of GPU use that were not the program's), and both tools named the run.

**Where and when:** same machine and date.

**Not tested:** the `suggested_actions` rules for shader-compile hitches (`perf_cold_warm`, `perf_compare` with a
`skip_s`), for throttling (`perf_ab` with `cooldown_s`) and for a run that stopped presenting: `drawstress` produced none of
them, so only the noisy rule was seen on a real run (the rest is covered by tests); the 20-point threshold is provisional and
was fitted on one quiet and one loaded run only; a cancel during `cooldown_s` on a real run (covered by a test).
