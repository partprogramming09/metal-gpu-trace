# Proof for 0.28.0

**Reader:** people

Each improvement below was run on the code of this release, on 2026-11-16 (see [README.md](README.md) for how a proof
is read). The recordings are real: `<runs>` holds a 15 s recording of `drawstress` in native Metal on Apple silicon
(run `real0c_20261116-184757`: 1 523 frames, 104.3 fps, the `.trace` kept, 91 MB) and `<runs-counters>` a 6 s recording
with GPU counters (run `cnt_20261116-221144`, a 90 MB `.trace`). Every command and output below was run again for this
file; paths and user names in the output are replaced by `~`, `<runs>` and `<runs-counters>`.

**Where and when (all of it):** macOS 27.0.1, Apple M1 Pro, Xcode 27.2; 2026-11-16.

## Every tool takes fields and the tool list is shorter

**Promise:** every tool takes an optional `fields` (dotted paths) that cuts its result before it is sent, keeping `total`,
`offset`, `rows` and `next_offset` on the paged tools; a path that matches nothing is named in `_meta.fields_missing`; a
`null` value is kept; and `tools/list` is shorter (45 186 characters in 0.27.3, measured at the time).

**Command:** the JSON-RPC handler of this code (`protocol.handle`) with `METAL_TRACE_OUT=<runs>`: `tools/list`, then
`tools/call` of `perf_runs` with `fields`.

**Output:**

```
tools/list: 26 tools, 33072 characters  (json.dumps(result, ensure_ascii=False); 0.27.3: 45186; the test's ceiling: 33500)

perf_runs {"fields": ["fps"]}
  {"total": 2, "offset": 0, "rows": [{"fps": 104.3}, {"fps": 104.3}], "next_offset": null, "project": null}
perf_runs {}   (same two runs, whole rows: 529 characters here; each row has 10 keys)
  {"total": 2, "offset": 0, "rows": [{"run": "real0c_20261116-184757", "schema_version": 3, "program": "--mtl", "frames": 1523,
   "fps": 104.3, "gpu_ms_mean": 5.855, "metal_mib_peak": 83.17, "rss_mib_max": 235.797, "trace_kept": true,
   "tables_kept": true, "layer": null}, {"run": "result", ...}], ...}

perf_runs {"fields": ["fps", "layer", "no.such.path"]}
  structuredContent: {"total": 2, "offset": 0, "rows": [{"fps": 104.3, "layer": null}, {"fps": 104.3, "layer": "native"}],
                      "next_offset": null, "project": null}
  _meta: {"fields_missing": ["no.such.path"]}
```

The path that matches nothing is listed and does not fail the call; `layer` is `null` in the first row and the `null`
is kept, not mistaken for a missing path. The size cut is 33 072 against 45 186, 27 % less.

**A real AI client using it.** `claude -p` (Claude Code, non-interactive) was given only this server over `<runs>` and
three tasks in Spanish: list the recordings asking only for label and fps; count GPU intervals per channel grouping in
the query; and name three arguments of the A/B tool without running it. It was run twice; the second time, now:


The first session of the day (recorded the same day, 3 tasks, 5 turns, 0 errors) gave the same counts (Compute 1 600,
Fragment 3 422, Vertex 3 434) and the same three arguments from the schema. The client asked for a `label` field that
does not exist, and the `fields_missing` answer is what let it move on to `run`.

**Not tested:** `fields` on every one of the 26 tools by hand (the tests cover each tool's schema); a client other than
Claude Code; a result so large that the size limit applies without `fields` and fits with it (tests only).

## metal-gpu-trace init sets the server up in one command

**Promise:** `metal-gpu-trace init` adds the server to the AI apps found on the machine (Claude Code, Claude Desktop,
Cursor, Codex CLI, and VS Code with `--project`) with absolute paths; `--dry-run` shows the change and writes nothing; an
existing JSON config is merged (other servers kept) with a `.bak` copy; it is safe to run twice.

**Command:** `init --dry-run` on this Mac (the real home folder is read, nothing is written), then the same dry run on a
copy of the real Claude Desktop config with this server taken out, and the suite of the command.

**Output:**


The real config already has the server and a second one (`gpu-tools`), so the dry run says "already configured" and
touches nothing. For the merge itself, the same file was copied to a throwaway home without `metal-trace` and the dry

The other server stays and this one is added with absolute paths. `tests/test_init.py` has 21 tests (they run in
`tests/run.py` below, with a fake home, never the real one).

**Run for real earlier the same day (not repeated here):** `init` was run without `--dry-run` on a real Claude Desktop
config: the other server was kept and the file kept its mode 600, after fixing a bug that loosened it to 644 (a test now
covers it).

**Not tested:** a real run of Cursor, Codex CLI and VS Code (Codex's TOML is shown, not written, and only through

## The tables are kept in a SQLite file and queried with filters

**Promise:** every recording keeps the tables its summary reads in `<run>.tables.sqlite`, so `trace_tables`,
`trace_count` and `trace_query` answer without the `.trace`; the same rows and the same totals as the `.trace` gives;
`trace_query` gains `where`, `columns`, `order_by`, `descending`, `group_by` and `aggregates` as filters, not SQL; home
folders are cleaned from the stored text; and GPU counter samples are not stored.

**Command:** `perf_runs` / `trace_query` of this code over `<runs>`. For each table the same page of 500 rows is asked
twice: with no filter (it reads the `.trace`) and with `columns` set to all the table's columns (it reads the SQLite
file); the rows are compared and each call timed.

**Output (the file, and the two paths):**


file that already exists (the 90 MB `.trace` was not summarized again: that takes about 90 s and rewrites the file).

**Not tested:** Windows (it has no `.trace`, so no tables file is written there); a counters
recording longer than 6 s (the fix drops the samples whatever their number, but only 6 s was run); a Wine/Direct3D 12
`.trace` (614 MB, not recorded for this release); the disk quota removing the tables file after the Chrome trace and
before the compressed tables (tests only); `PERF_TABLES=0` (tests only).

## The standard-library-only rule is lifted

This is a rule, not an improvement a reader runs: see [ADR-0008](../adr/0008-lift-the-standard-library-only-rule.md).
Python 3.9 stays the floor, and the SQLite file reads through `sqlite3`, which is in the standard library.
