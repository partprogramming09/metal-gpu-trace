# Proof for 0.27.2

**Reader:** people

Each improvement below was run on the code of this release, on 2026-11-16 (see [README.md](README.md) for how a proof
is read). Every recording was made with the Mac session **locked** and `METAL_TRACE_ALLOW_LOCKED=1`, so the native
windows were not paced by the display: read the latency and allocation numbers, not the FPS.

## How long the GPU takes to start

**Promise:** the summary says how long the GPU takes between receiving the work and starting it, and `perf_compare`
compares its median.

**Command:** `perf_record` of `drawstress` (`api=mtl`, `wine="native"`, `seconds=20`, `tier=standard`); then a
`tier=deep` run (`seconds=8`, `counters=false`, so the `.trace` is kept) whose `metal-gpu-intervals` table was read again
outside the summary code and the median taken with `statistics.median`.

**Output:**

```
gpu.start_latency_ms (20 s): {count: 6103, mean: 2.396, p50: 0.602, p95: 6.056, max: 27.565}
gpu.start_latency_ms (8 s):  {count: 2414, mean: 2.368, p50: 0.559, p95: 6.026, max: 16.066}
median of the 2424 rows of the 8 s table, by hand: 0.56 ms
```

**Where and when:** macOS 27.0.1, Apple M1 Pro, Xcode 27.2; 2026-11-16.

**Not tested:** the 10 rows between 2424 and 2414 are the rows the summary leaves out because they were not presented;
that was not checked row by row. `perf_compare` on two real runs (covered by tests only). Windows has no such table.

## How many other processes load the GPU

**Promise:** with `noisy_environment` true, `noisy_basis.other_processes` says how many other processes used the GPU,
their GPU milliseconds and their share of all GPU time. It never names a process, so no program the person runs
reaches a summary that is shared.

**Command:** a second `drawstress --mtl` was started by hand and left running; then `perf_record` of `drawstress`
(`api=mtl`, `wine="native"`, `seconds=20`, `tier=standard`).

**Output:**

```
noisy_environment: true
noisy_basis: {gpu_device_pct_mean: 86.2, process_busy_pct: 47.7, external_pct: 38.5,
              other_processes: {count: 2, gpu_ms: 9572.662, share: 0.503}}
```

A quiet run (the first one above) has `noisy_environment` false and no `noisy_basis`.

**Where and when:** same machine and date.

**Not tested:** which two processes those were (the count has no names by design: one is the second `drawstress`, the
other was not identified); a real run with no other process (tests only). Windows has no such field.

## What is still allocated at the end

**Promise:** `resource_allocations` says what was still allocated when the recording ended, by memory mode and by type,
how much was freed, and how many frees had no allocation in the recording. It is a lower bound: what was allocated
before recording does not show.

**Command:** the 20 s `tier=standard` run above, and the 8 s `tier=deep` run, whose table was paired again by
`resource-id` outside the summary code.

**Output:**

```
20 s: events 6142, live {count: 65, mib: 81.9,
        by_mode: {Managed: 3 / 0.4, Private: 2 / 0.2, Shared: 55 / 68.5, unknown: 5 / 12.8},
        by_type: {Buffer: 60 / 69.1, Texture: 5 / 12.8}},
      freed {count: 6077, mib: 8093.0}, freed_before_recording 14
8 s, summary: live 65 / 81.9 MiB, freed 2405, freed_before_recording 14
8 s, by hand: live 65 / 81.9 MiB, freed 2405, freed_before_recording 14
```

**Where and when:** same machine and date.

**Not tested:** a trace that really leaks (this program keeps 65 resources and no more in either length); the
`Memoryless` mode on a real run (tests only).

## Shader register spills

**Promise:** the summary counts the shader register spills of the recorded program, and `perf_diagnose` says so when
there are some.

**Command:** the 20 s and 8 s runs above.

**Output:**

```
shader_spills: {events: 0}     (both runs; graphics-compiler-spill-events present, no row of the program)
```

**Where and when:** same machine and date.

**Not tested:** a program that spills. No real recording here had a spill event, so the positive case (`events`,
`bytes`, `encoders` and the `perf_diagnose` line) is covered only by tests with synthetic rows: this is why it ships as
experimental.
