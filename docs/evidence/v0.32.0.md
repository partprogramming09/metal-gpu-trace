# Proof for 0.32.0

**Reader:** people who want to see that each improvement of 0.32.0 was run, with the command and its real output.

Each improvement below was run on the code of this release, on 2026-11-26 (see [docs/evidence/README.md](README.md) for how a proof is read). The recordings are real: the `drawstress` test program in native Metal (`workload_fetch` downloaded it), 12 s each, on this Mac, plus one recording of 2026-11-19 of the same program. Paths and machine names are left out of every output.

**Where and when (macOS):** macOS 27.2.1, Apple M1 Pro, Xcode 27.2, Python 3.15.0; 2026-11-26.

## An honest A/B records what it was made with

**Promise:** `fingerprint_paths` on `perf_ab` and `perf_record` stores a short hash of each file you name in the summary's `context`; the variable names of `env` (never the values) go to `context.env_keys`; `perf_compare` reports both, and warns when two runs are more than 24 hours apart.

**Command:** `perf_ab` with `env_a` empty, `env_b` = `PROOF_VAR=1`, `workload` = `drawstress`, `api` = `mtl`, `seconds` = 12, `tier` = `light`, `fingerprint_paths` = the program's binary (one round: A B B A, 4 recordings); then `perf_compare` of a run of 2026-11-19 and the first A run.

**Output:**

## perf_sweep measures a column of the program's telemetry

**Promise:** `perf_sweep` with `metric="app_metrics.<column>"` returns, per value, the median over rounds of that column's mean, and `app_fit` (a line, with its r2) beside the GPU `fit`.

**Not proven now:** the program that wrote such a telemetry file in the earlier proof (a native Metal program with a `cpu_ms` column) is no longer on this machine, and `drawstress` writes no telemetry file. The behaviour is covered by `tests/test_app_metrics.py` and `tests/test_analysis.py`; until a real program is swept, the improvement stays 🧪.

## preflight says when the GPU is busy

**Promise:** before a recording on a Mac, `preflight` and `doctor` read the whole machine's GPU use and say `busy`, with the percentage, when it is 20 % or more; they never refuse the recording.

**Command:** `metal-gpu-trace doctor` with the machine idle, then while `drawstress --mtl` runs in another process (`ioreg` showed 69 % at that moment).

**Output:**

```
$ metal-gpu-trace doctor            (idle)
ok       gpu
$ metal-gpu-trace doctor            (drawstress running)
busy     gpu: the GPU is 67.7 % busy before the recording starts: something else is using it (a game, a browser tab, a render), and its load lands in the numbers; close it, or record anyway and read the summary's noisy_environment flag
ok: a recording can start
```
