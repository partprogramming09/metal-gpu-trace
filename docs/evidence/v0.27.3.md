# Proof for 0.27.3

**Reader:** people

Each improvement below was run on the code of this release, on 2026-11-16 (see [README.md](README.md) for how a proof
is read). Every recording was made on `drawstress` in native Metal (`workload="drawstress"`, `api="mtl"`,
`wine="native"`, `seconds=20`, `tier=standard`), with the Mac session unlocked.

One caveat for all of them: another job was using the Mac at the same time, and three of the four recordings
(`a`, `c`, `d`) stopped drawing after about 4 s (194 to 262 frames instead of about 2 000, a gap of 0.8 s at frame
200 to 268 with 4 % CPU). Only run `b` is clean (2 017 frames in 20.8 s). Memory numbers below come from `b`; the
`perf_check` comparison uses the median frame interval, which the stall barely moves.

## A summary has a common block on both platforms

**Promise:** a new summary carries `schema_version` 3 and a `common` block (frame pacing, memory pressure, graphics API)
with the same keys on macOS and Windows and a `source` per number; what cannot be measured the same way on both is
`{"comparable": false, "reason": ...}`, never an invented number.

**Command:** `perf_record` of `drawstress` as above; the `common` block of run `b` read from its saved summary.

**Output:**

```
schema_version: 3
common: {
  frame_pacing: {fps_estimate: 102.5, fps_1pct_low: 90.3, fps_01pct_low: 64.0, stutter_rate_pct: 0.25,
                 frame_jitter_ms: 0.575, source: "xctrace"},
  memory_pressure: {peak_mib: 83.17, source: "metal-allocated"},
  boundness: {comparable: false, reason: "CPU and GPU time are measured differently on each platform"},
  submission_overhead: {comparable: false, reason: "only Metal records command buffers and encoders"},
  api: {runtime: "metal", translation_layer: "native"}
}
```

**Where and when:** macOS 27.0.1, Apple M1 Pro, Xcode 27.2; 2026-11-16.

**Not tested:** a real Windows recording writing the same block, and `perf_compare` between a macOS and a Windows
summary (both covered by tests only). Older summaries reading is covered by tests.

## What a recording allocated, by type

**Promise:** `perf_memory_breakdown` splits a saved recording's Metal allocations by type, says what is still live, and
gives how many times over the live memory was allocated and the allocation rate after start-up, from the summary alone.

**Command:** `perf_memory_breakdown(run="<run b>")`.

**Output:**

```
events 4107, allocated 464.0 MiB (2.04 per frame), live 66 / 84.8 MiB, freed 4041 / 379.1 MiB, freed_before_recording 14
allocated_mib_per_live_mib 5.47, events_per_s_after_3s 202.6, peak_metal_mib 83.17
Buffer:  allocated 4100 / 448.0 MiB (mean 0.109), live 60 / 69.1 MiB, live_share_pct 15.4, gone 4040
Texture: allocated    7 /  16.0 MiB (mean 2.286), live  6 / 15.7 MiB, live_share_pct 98.1, gone 1
```

The types add up to the totals (4 100 + 7 = 4 107 events; 448.0 + 16.0 = 464.0 MiB; 60 + 6 = 66 live).

**Where and when:** same machine and date.

**Not tested:** the figures against the raw `.trace` table (the live and freed totals match the earlier hand count
in [0.27.2](v0.27.2.md#what-is-still-allocated-at-the-end), which this tool reads); a recording that really churns
memory (this program keeps 66 resources); a recording from before 0.27.0 (tests only).

## perf_check says when its reference is one run

**Promise:** when the verdict is not `same` and the reference is a single run, `perf_check` adds a `note`: the range is a
point, so the noise between equal runs is not measured and a small change may be noise. The verdict does not change.

**Command:** `perf_baseline(name, runs=["<run b>"])`, then `perf_check(run="<run d>", baseline=name, margin_pct=3)`
and with `margin_pct=0` (the default margin is too wide for two equal runs to leave the range).

**Output:**

```
margin_pct 3: verdict same, regressed [], improved []                      (no note)
margin_pct 0: verdict regressed
  regressed: fps 102.3 against range 102.5 to 102.5
  improved:  gpu_ms_mean 5.723 against range 5.755 to 5.755
  note: "the reference is one run, so its noise is not measured and a small change may be noise;
         save 2 or more runs with perf_baseline"
```

**Where and when:** same machine and date.

**Not tested:** two clean runs (run `d` is one of the disturbed ones); a reference of several runs, which carries its
noise in its range and adds no note (tests only).
